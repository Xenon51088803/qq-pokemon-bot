# 宝可梦机器人 · 全国图鉴与每日探索

Python 3.12+ · SQLite · Pillow · QQ 官方机器人 · [MIT 源码许可证](LICENSE)

全国编号 #001～#1025，涵盖九个世代的默认形态。不需要 QQ 账号或密钥，可先在本地体验每日探索、自动收集和图片图鉴。已有官方机器人时，按 [QQ接入说明.md](QQ接入说明.md) 配置并启动 QQ 接入；真实群权限及发送效果需要使用你的账号验收。

开源仓库：<https://github.com/Xenon51088803/qq-pokemon-bot>。首次下载后安装 Python 3.12 或更新版本，双击 **安装依赖.cmd**，再启动模拟器或配置 QQ 机器人。仓库包含 1025 种本地图鉴资源，普通运行无需下载素材。

需要电脑关机后继续在线，可按 [服务器部署说明](服务器部署说明.md) 安装到 Debian 12 服务器，使用 systemd 后台运行和开机启动；安装入口会为该服务器准备独立的 Python 3.12 环境。

## 开始使用

1. 双击 **启动模拟器.cmd**。
2. 输入 `@机器人` 或 `@机器人 探索`，获得当天的 10 只宝可梦和一张汇总图片。
3. 输入 `@机器人 图鉴` 查看总览，或 `@机器人 图鉴 1 1` 查看第一世代第 1 页。
4. 回复中的“图片”后面是本机文件路径，用文件管理器打开即可。所有生成图片也可在 `runtime/simulator/images` 找到。

启动器优先寻找项目虚拟环境，其次寻找本机已有的 Python 3.12 和 Pillow（包括当前 Codex 附带的运行环境）。本机可直接使用；复制到其他电脑时，先安装 Python 3.12 或更新版本，再双击 **安装依赖.cmd**。首次安装依赖需要联网。

已准备的素材可离线运行。素材缺失时双击 **更新资源.cmd**，该操作需要联网；无法下载的图片会显示灰色占位，不影响捕捉。不要删除 `assets/pokemon.json`。

## 玩法指令

| 消息 | 功能 |
|---|---|
| `@机器人` 或 `@机器人 探索` | 每日一次探索，获得 10 只并自动捕捉 |
| `@机器人 皮卡丘` | 独立资料查询：图片、介绍、分类、属性、身高和体重 |
| `@机器人 图鉴` | 全国与各世代完成度总览 |
| `@机器人 图鉴 1` | 第一世代第 1 页 |
| `@机器人 图鉴 1 2` | 第一世代第 2 页，页码为 1～6 |
| `@机器人 图鉴 9 1` | 第九世代第 1 页，世代范围 1～9 |
| `@机器人 图鉴 全国 1` | 全国图鉴第 1 页，共 35 页 |
| `@机器人 图鉴 皮卡丘` | 单只资料、捕捉次数和日期 |
| `@机器人 我的收集` | 已收集种类数、总次数、最近捕捉 |
| `@机器人 成就` 或 `@机器人 我的成就` | 查看 15 项收集成就、解锁日期和进度 |
| `@机器人 帮助` | 指令说明 |

支持全国编号 1～1025 的默认形态，不将地区形态、Mega、异色等另算收集种类。基础抽取等概率、允许重复，并叠加每日未收集保底。图鉴每页最多 30 只，第一世代仍为 6 页，末页只有 #151 梦幻；全国共 35 页，末页为 #1021～#1025。图鉴查询不会捕捉；未拥有的宝可梦在分页里显示占位，单只资料查询可以看到它的图片。

直接发送 `@机器人 妙蛙种子`、`@机器人 利欧路` 或 `@机器人 桃歹郎`，可查看对应的资料卡片和完整中文介绍，尚未收集也可查询。资料查询与个人收集图鉴独立，不写入收藏、不消耗每日探索、不触发成就；第一世代分页继续单独以 151 为分母，`@机器人 图鉴 皮卡丘` 继续查询个人捕捉记录。名称输错或不在全国 1025 种范围内时会给出提示，不会自动探索。

介绍采用 PokeAPI 收录的中文游戏图鉴文本，缺失部分由宝可梦中国官网补齐，属性采用普通形态的现行属性（例如皮皮为妖精属性）。全部资料和图片已保存在本地，运行时无需联网查询；资料查询沿用 15 秒图鉴间隔和群图片频率限制。

每天北京时间零点换日，无需重启或清空数据。一次探索先独立随机抽取 10 只；如果整批都已拥有，且当前抽池仍有未收集种类，就将最后一只替换为从未拥有种类中等概率抽取的一只。自然抽到新种类时不再额外补一只，抽池集齐后关闭保底。每批始终为 10 只，允许批内重复，每只均增加一次捕捉次数；同一种在本批首次出现时才计为新发现。

同群、同人、同日的整批结果和保底标记持久保存；重复 @、并发请求和重启不会重新抽取、再次保底或增加次数。QQ 以一张汇总图片展示十只，不逐只发送。

## QQ 输入框指令面板

使用 QQ 官方的**群聊指令面板**接口注册菜单，供客户端在输入区展示。包含 `探索`（每日十连）、`我的收集`、`图鉴`、`图鉴 全国 1`、`图鉴 1 1`、`成就`、`皮卡丘`（资料查询示例）和 `帮助`，普通成员均可操作。显示名称就是填入的指令；点击“皮卡丘”后可改成其他宝可梦名字再发送。

官方文档说明点击指令会填入聊天输入框，**仍需点击发送**，该面板接口没有自动发送字段。能否在选中 @ 时显示及具体布局取决于 QQ 客户端和账号能力，需在真实 QQ 群验收；不能通过机器人服务端强制弹出客户端界面。此配置沿用现有指令，单独发送 @ 仍为每日探索，收藏图鉴和翻页功能保持原样。

在已部署的 Debian 服务器上执行（无需停止或重启机器人）：

```sh
git -C /YCX/qq-pokemon-bot pull --ff-only origin main
cd /YCX/qq-pokemon-bot
runuser -u pokemonbot -- .venv/bin/python -X utf8 -m pokebot.qq_panel --apply
```

如果更新代码失败，请先处理报错。工具使用服务器已有的 `qq.local.json`，不显示密钥，不连接消息网关，不发送群消息，不读写收藏数据库。成功后在 QQ 群输入框重新选择 @机器人，检查是否展示指令，并点击选项后发送验收。

Windows 也可双击 **配置QQ指令面板.cmd** 注册面板；应选服务器或电脑其中一处执行，不要同时运行。仅查看将要配置的内容时，在项目目录运行 `python -m pokebot.qq_panel`，此模式不读取凭证、不联网。

工具先完整查询已有群聊面板，只更新带本项目标记的全局面板；配置相同则跳过。若已有其他全局面板或重复面板，会停止并保留原配置。已有指定群面板不作修改，可能影响相应群的显示，需要在平台另行核对。写入后会回读核验；网络中断或回读未确认时不声称成功，也不自动重试创建，稍后重新执行会先查询。遇到权限错误时保留 HTTP 状态与平台错误码，检查指令面板能力、服务器 IP 白名单及网络。

依据：[官方面板说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/menu-panel/)、[创建指令面板](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_panels.post.html)。接口注册成功仍需客户端验收。

## 翻页与收集成就

图鉴第一条回复在页码和收集进度下方直接附带“上一页／下一页”按钮，图鉴图片随后发送；首页只有下一页，末页只有上一页。QQ 群里点击按钮会填入命令，**仍需点击发送**，仅发起查询的成员可使用该条回复上的按钮。若 QQ 明确拒绝按钮，程序回退为附有文字翻页命令的完整图鉴回复；客户端不支持时也可手动发送 `@机器人 图鉴 1 页码`。翻页沿用图鉴冷却时间（默认 15 秒），不会增加捕捉记录。

| 成就 | 条件 |
|---|---|
| 初次相遇 | 首次捕捉 |
| 小有收藏 | 收集 10 种 |
| 收藏达人 | 收集 50 种 |
| 关都专家 | 收集 100 种第一世代宝可梦 |
| 关都大师 | 集齐第一世代 151 种 |
| 御三家集结 | 集齐妙蛙种子、小火龙、杰尼龟（进化形态不替代） |
| 第 2～9 世代大师（8 项） | 分别集齐对应世代 |
| 全国图鉴大师 | 集齐全国 1025 种 |

成就按本群、本成员收藏计算，不奖励额外探索；原有关都成就仅计算第一世代，其他世代收藏不会误触发。新解锁随当次捕捉文字和卡片展示；重复抽取、重复查询和重启不会再次提示解锁。发送失败后仍可通过“成就”查询解锁记录。

已有收藏首次启动新版时自动补认，解锁日期按历史首次捕捉日期计算，不逐条发送通知。从旧版本升级前自动保存 `backups/before-national-v3.sqlite3`，保留旧捕捉次数、日期和成就；版本 1／2／3 的旧备份仍可恢复。北京时间 2026 年 10 月 15 日已完成旧版单抽的成员，当天再次发送 `@机器人 探索` 可额外领取一次十连补抽，原单抽记录保留，补抽同样享有未收集保底。每人每群仅限一次，重复消息、并发和重启均不会重复发放；已经完成新版十连的成员不追加补抽。尚未抽过的成员当天即可正常探索十只。其他日期沿用每日一次规则。

## 模拟群和成员

默认身份为“测试群A / 小智”。模拟器操作不发送给机器人：

```text
/群 测试群B
/成员 小霞
/按钮 1
/状态
/私聊 @机器人
/备份
/退出
```

模拟群名和成员名就是本地标识，换名字会切换收藏；切回原名称可继续原记录。真实 QQ 使用平台群和成员 OpenID，不会用昵称作为主键。模拟器用 `@机器人` 文字识别提及；QQ 适配器使用平台的结构化事件。未 @ 消息和私聊会被忽略。

模拟器不提供改日期、补抽或修改抽取结果的指令。终端中无需输入开头的 `>`。

查询图鉴分页后，回复下方显示带编号的翻页按钮，输入 `/按钮 1` 操作第一个按钮。切换群或成员会清空旧按钮；无效编号只给提示，不触发抽取。

## 配置和频率

将 `config.example.json` 复制为 `config.local.json` 后修改，重启生效：

- `pool_min` / `pool_max`：默认 1 和 1025，只允许在 1～1025 内缩小范围。保底只从当前范围的未拥有种类中选择。已有当天结果不受配置变化影响，全国分母固定 1025、各世代分母独立。若沿用旧版配置，请将 `pool_max` 从 151 改为 1025，重启后生效。
- `draw_cooldown_seconds`：普通请求间隔，默认同群同人 3 秒。
- `dex_cooldown_seconds`：图鉴、详情、总览图片请求间隔，默认 15 秒。
- `group_images_per_minute`：每群每分钟图片上限，默认 10。达到上限仍可返回文字，抽取结果仍会保存。
- `cache_max_mb` / `cache_days`：生成图片缓存默认最多 500 MB，7 天未访问自动清理。每分钟有消息触发时检查一次，允许短暂超出限制；不删除素材或收藏。
- `render_workers` / `render_queue_limit`：默认 2 个图片工作线程、最多 16 个在途图片任务；满时返回文字。
- `font_path`：默认使用 Windows 微软雅黑。其他系统需要中文字体，可配置字体文件的绝对路径。

限流提示最多每 15 秒一次，连续刷屏可能不回复。首次体验多个图鉴指令时请稍等，或在本地配置中将两项 cooldown 设为 0；正式群聊建议保留限流。

## 数据、备份与恢复

本地收藏在 `runtime/simulator/collection.sqlite3`，测试使用临时数据库，不污染收藏。QQ 版使用独立的 `runtime/qq/`，不复用模拟器数据库。

每日首次启动或首次收到消息时，创建一致性备份，保留最近 7 份日备份及 4 份周备份。自动备份是当时的数据快照，并非持续同步；重要操作后可输入 `/备份`。手动备份不自动清理。

关闭模拟器后也可双击 **手动备份.cmd**。恢复步骤：

1. 关闭所有模拟器窗口。
2. 在项目目录的 PowerShell 中运行：

```powershell
.\scripts\start.ps1 -Restore 'C:\完整路径\daily-2026-10-14.sqlite3'
```

恢复前会校验文件并自动备份现有数据库，再替换模拟器收藏。不要直接复制运行中的 SQLite 主文件，因为尚未合并的数据可能在 WAL 文件中。同盘备份不能防止硬盘损坏；重要备份请另存到其他设备。

日志位于 `runtime/simulator/logs`，每份最多 2 MB，保留 5 份历史日志，不记录聊天正文。进程锁可防止同一个模拟目录被同时启动或在运行中恢复。

## 测试与开发

双击 **运行测试.cmd**，或在 PowerShell 执行：

```powershell
.\scripts\start.ps1 -Test
.\scripts\start.ps1 -Once '@机器人 我的收集'
```

源代码位于 `pokebot/`：`BotService.handle(Message)` 是 QQ 适配器的入口。消息包含群 ID、成员 ID、消息 ID、有时区的发送时间、文本及群聊／提及标记；回复包含目标群、应 @ 的成员 ID、文字、可选的本地图片路径及命令按钮。业务服务异步执行，图像在线程池中生成。数据库版本为 4，十只探索或升级补抽、逐只捕捉和成就写入在同一事务内提交。升级自动备份并迁移版本 1／2／3 数据库；版本 3 升级备份为 `backups/before-upgrade-bonus-v4.sqlite3`。补抽使用独立记录，保留原来的单只结果；恢复备份也会恢复领取状态、整批结果与保底状态。

日期使用消息发送时间换算为北京时间。超过 5 分钟的积压消息或明显来自未来的消息被忽略。成功保存捕捉后才生成回复，发送失败时不回滚捕捉；用户重新发起请求仍取回同一结果。相同消息 ID 的平台重推在本地去重，不重复返回回复；新消息 ID 的重复 @ 会返回当天结果。

QQ 接入模块已实现官方鉴权、事件接收、@ 解析、图片上传及消息发送、接口重试和断线重连。官方账号权限、图片上传及手机 QQ 压缩后的显示仍需真实群验收，本地测试不能替代。
